# 概要设计：dsh-pet-assets 管理平台路由化 + UI 优化

## 设计总览

### 需求背景

`dsh-pet-assets` 是 dsh-pet（傲娇猫桌宠）的资源管理平台：独立本地 HTTP 服务 + 管理员登录 + SQLite，负责托管/维护桌宠的透明 webm 动画资源。

本次改造聚焦**管理平台前端**的架构与体验问题：

1. **视图切换靠 `v-if` 而非路由**：`App.vue` 用 `v-if/v-else-if` 切换登录页/后台；`Admin.vue`（661 行）用 `activeMenu` 局部状态 + 一串 `v-if/v-else-if` 模板切换 7 个视图。无 URL、无浏览器前进/后退、无刷新保持、无守卫，视图即逻辑内联在单文件里，难以维护与扩展。
2. **弹窗与页面职责未分离清晰**：编辑动作已是 `el-dialog`（应保留为弹窗），但 7 个业务模块全部内联渲染在同一 `Admin.vue`，既不是独立页面、也不是独立组件。
3. **整体 UI 需优化**：侧边栏是手写 `div` 导航（无路由语义、无键盘可达性），各视图面板样式零散，缺少统一的页面头/加载/空态规范。

## 整体业务交互链路

### 场景 1：登录进入后台

```
用户 → /login 表单 → POST /api/auth/login（set-cookie）→
  mustChangePassword=true ? 登录页内联改密表单（POST /api/auth/change-password）→ 成功回到登录表单
  : router.replace(/dashboard) → 布局挂载 → 加载共享数据 → 渲染仪表盘
```

| 步骤 | 参与方 | 动作 | 接口/说明 |
|------|--------|------|---------|
| 1 | 用户 | 输入账号密码提交 | 前端本地校验非空 |
| 2 | 前端 | 调登录接口 | `POST /api/auth/login` |
| 3 | 后端 | 校验 scrypt 密码、签发 session | `200 {mustChangePassword}` 或 `401` |
| 4 | 前端 | 依据 `mustChangePassword` 分流 | 改密子流程 或 跳后台 |
| 5 | 后端 | 改密 | `POST /api/auth/change-password`，撤销全部会话 |

### 场景 2：动作库维护（上传/编辑/删除/重建）

```
用户(/library) → 列表 GET /api/resources → 卡片网格渲染 →
  上传(el-upload→POST /api/resources?category=)→ 刷新列表
  编辑(打开 el-dialog→PATCH /api/resources/{file})→ 刷新列表
  删除(ElMessageBox 二次确认→DELETE /api/resources/{file})→ 刷新列表 + 回收站徽标
  重建(POST /api/rebuild)→ 刷新列表
```

| 步骤 | 参与方 | 动作 | 接口/说明 |
|------|--------|------|---------|
| 1 | 前端 | 进入 `/library` 拉列表 | `GET /api/resources` |
| 2 | 用户 | 上传/编辑/删除/重建 | 对应写接口 |
| 3 | 后端 | 写资源并落审计 | 写接口均需 session，401 时前端登出 |
| 4 | 前端 | 成功后刷新列表与统计 | 触发共享 store 的 `loadResources/loadTrash` |

### 场景 3：桌宠控制台下发命令

```
用户(/console) → 选动作/输入文本 → POST /api/pet/commands → 列表刷新（最近命令）→ 桌宠端 /api/pet/poll 拉取执行
```

| 步骤 | 参与方 | 动作 | 接口/说明 |
|------|--------|------|---------|
| 1 | 用户 | 点击动作/输入文本 | 本地校验 |
| 2 | 前端 | 下发命令 | `POST /api/pet/commands` |
| 3 | 后端 | 入队 + 审计 | `200` |
| 4 | 前端 | 刷新最近命令 | `GET /api/pet/commands` |
| 5 | 桌宠端 | 轮询执行并回执 | `GET /api/pet/poll`、`POST /api/pet/commands/{id}/done` |

### 场景 4：回收站 / 审计 / 健康检查

```
用户(/trash|/audit|/health) → 对应 GET 接口 → 表格/结果渲染 → 恢复/彻底删除/重新检查
```

## 建议开发顺序

| 顺序 | 工程/模块 | 原因 |
|------|---------|------|
